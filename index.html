How it's computed

Expected counts — for each cell, Eᵢⱼ = (row total × column total) ⁄ grand total — the count that would be expected if the row and column variables were independent.

Test selection (Cochran's criteria) — if any expected count is below 1, or more than 20% of cells have an expected count below 5, the chi-squared approximation is considered unreliable, and an exact test is used instead: Fisher's exact test for a 2×2 table, or the Fisher–Freeman–Halton exact test (the same idea generalized to any number of rows/columns) for larger tables. Otherwise, Pearson's chi-squared test of independence is used, with Yates' continuity correction also shown for 2×2 tables.

Fisher–Freeman–Halton — enumerates every possible table with the same row and column totals as the one observed, computes the exact hypergeometric probability of each, and sums the probabilities of every table at least as improbable as the one observed — the exact multi-category generalization of Fisher's exact test, needing no large-sample assumption. This is validated in this app by confirming it reproduces the 2×2 Fisher's exact result exactly on 2×2 tables. Enumeration is only feasible for reasonably small tables — if a table is too large to enumerate in the browser, this tool falls back to the chi-squared approximation and says so explicitly, rather than silently reporting an unreliable number as if it were exact.

Cramér's V — √(χ²⁄(N×min(r−1,c−1))), an effect size between 0 (no association) and 1 (perfect association) that, unlike the p-value, doesn't shrink automatically as the sample size grows.

Odds ratio / relative risk (2×2 only) — computed the same way as the Contingency table tab, with a 0.5 continuity correction applied to all four cells when any cell is zero, and 95% Wald confidence intervals on the log scale.

Category filtering — unchecking a category removes every row containing that value from the cross-tabulation and the test — it does not merge it into the other categories. Excluding categories changes the effective sample size and margins, so the test re-runs on exactly the filtered data shown in the table above it.

Not implemented — Monte Carlo approximation for large tables that exceed the exact-enumeration limit (the tool falls back to the ordinary chi-squared approximation instead), and multi-way (three or more variable) pivot tables.

Step 2

Normality check

Why Shapiro–Wilk — of the common normality tests (Kolmogorov–Smirnov, Lilliefors, Anderson–Darling, D'Agostino–Pearson), comparative power studies (Razali & Wah, 2011) consistently find Shapiro–Wilk the most powerful at detecting non-normality across most alternative distributions — especially at the small-to-moderate sample sizes typical here. p-values use Royston's (1995) approximation, valid for 3–5000 observations. A significant result (p < 0.05) is evidence against normality — reason to consider a non-parametric alternative (Mann–Whitney U for independent samples, Wilcoxon signed-rank for paired) instead of the t-test. With very small samples the test also has limited power, so a non-significant result here isn't strong proof of normality either — it mainly means no departure was detected.

Visual check

Distribution

Each histogram picks its own bin width from its data via the Freedman–Diaconis rule (2·IQR⁄∛n) — wider spread gives wider bins, and it's robust to outliers since it's based on the interquartile range rather than the min/max. The two histograms aren't on a shared scale, so compare shape, not bar-to-bar height. This is the visual complement to the Shapiro–Wilk check above.

Step 3

Equality of variance

Why Levene's test — it tests equality of variance using deviations from each group's median rather than its mean (the Brown–Forsythe form), which keeps it reliable even when a group isn't perfectly normal — unlike the plain F-test, which assumes normality itself. A significant result (p < 0.05) means the two groups' spreads differ enough that pooling them (Student's t-test) would understate or overstate the standard error — use Welch's t-test instead.

Normality check

Why Shapiro–Wilk — Pearson's r assumes both variables are approximately normally distributed; Shapiro–Wilk is the most powerful common test for flagging when that assumption doesn't hold (Razali & Wah, 2011), which is why it's used here to help decide between Pearson's r and Spearman's rank correlation.

Step 3

Linearity check

Why this test — Pearson's r and linear regression both assume the relationship is a straight line, not merely monotonic. This is a curvature test: it fits a quadratic term (y = b₀+b₁x+b₂x²) alongside the linear one and checks, via an F-test, whether that curvature term explains significantly more variance than the line alone. A significant result (p < 0.05) is evidence the relationship bends — reason to prefer Spearman's rank correlation over Pearson's r, and to treat a linear regression fit with caution. It complements, but doesn't replace, looking at the scatter plot above.

Step 4

Regression diagnostics

Why these tests — linear regression's significance tests additionally assume the residuals (actual − predicted) are normally distributed and have constant variance across X (homoscedasticity). Residual normality is checked with Shapiro–Wilk again, this time on the residuals. Constant variance is checked with the Breusch–Pagan test: it regresses the squared residuals on X and tests whether that explains a significant share of their variance (via n·R², a chi-squared statistic with 1 df) — a significant result (p < 0.05) means the spread of residuals changes across X, so standard errors on the slope may be misleading.

How it's computed — Pearson's r is the standardized covariance of X and Y; its significance test uses t = r√((n−2)⁄(1−r²)) with df = n−2. About Kaplan–Meier analysis

What it is — Kaplan–Meier estimation tracks the probability of "surviving" (not yet having the event) over time in a group that includes some incomplete observations. It's the standard way to summarize time-to-event data — death, relapse, device failure, discharge — when not everyone has been followed for the same length of time or reached the event by the end of the study.

Event vs. censoring — An event (coded 1) is the outcome you're tracking actually happening. A censored observation (coded 0) is someone who left the risk set without the event happening — the study ended, they were lost to follow-up, or they withdrew. Censoring is not a negative result and is not the same as loss to follow-up in general — it specifically means "we know they hadn't had the event as of this time, but we don't know what happened after."

The formula — Ŝ(t) = Πtᵢ≤t (1 − dᵢ⁄nᵢ), where nᵢ is the number still at risk just before time tᵢ and dᵢ is the number of events at tᵢ. The curve only steps down at event times; a censoring removes someone from the risk set for later times but doesn't itself drop the curve.

Median survival — the earliest time at which the estimated survival probability falls to 0.50 or below — i.e., the point by which half the cohort has had the event. If the curve never reaches 0.50 during follow-up, the median is genuinely not known yet; reporting the last observed time as if it were the median would be wrong, so this app says "not reached" instead.

Confidence intervals — computed with Greenwood's formula for the variance of Ŝ(t), combined with a complementary log-log transformation before building the interval and transforming back. This keeps every confidence bound inside [0, 1] and is generally more accurate than a plain linear interval, especially near the ends of the curve.

The log-rank test — compares two Kaplan–Meier curves by summing, at every time an event occurs in either group, the difference between observed and expected events in one group (expected under the null hypothesis that both groups share the same survival function), weighting by the hypergeometric variance at each time. It tests whether the two survival distributions differ over the whole observed follow-up — it does not estimate the size of the difference (that's what a hazard ratio from a Cox model is for), and it can be underpowered if the two curves cross, or if either group has few events.

Statistical vs. clinical significance — a small p-value only says the observed difference is unlikely under the null hypothesis given this sample; it says nothing about whether the difference is large enough to matter clinically, and a non-significant result with a small sample doesn't prove the groups are equivalent. Curves, medians and p-values here should be read alongside the actual sizes of the effects and confidence intervals, not the p-value alone.

Not yet implemented

Cox proportional hazards model

A hazard ratio should come from a Cox model, not be read off Kaplan–Meier curves or computed from median survival times — both would misrepresent the comparison. That model isn't implemented in this tool yet, so no hazard ratio is shown here. Use the log-rank test above for whether the curves differ, and treat any hazard ratio you compute elsewhere as a separate analysis from this one.

How it's computed — The Kaplan–Meier estimator is Ŝ(t) = Π(1−dᵢ⁄nᵢ) over each distinct time with an event, ties handled by counting dᵢ and nᵢ as totals at that time rather than breaking them apart. Variance uses Greenwood's formula, Σdᵢ⁄(nᵢ(nᵢ−dᵢ)), transformed via complementary log-log for the 95% bands. Median survival and its CI are read directly off the step function and its confidence bands — never approximated from the last observed time or interpolated. The log-rank test is the Mantel–Haenszel form: at each pooled event time it compares observed vs. expected events in one group under the shared-survival null, weighted by the hypergeometric variance, summed and squared against that total variance (χ², df = 1). No hazard ratio is computed from these curves.

Step 2

Normality check

Why Shapiro–Wilk — standard ANOVA assumes each group is approximately normally distributed; Shapiro–Wilk is the most powerful common test for flagging when that assumption doesn't hold (Razali & Wah, 2011). If any group departs from normality, this tool looks for a transformation before falling back to the fully non-parametric Kruskal–Wallis test.

Step 3

Equality of variance

Why Levene's test — generalized to k groups as a one-way ANOVA on each group's deviations from its own median (the Brown–Forsythe form), which stays reliable even when a group isn't perfectly normal. A significant result (p < 0.05) means the groups' spreads differ enough that standard ANOVA's equal-variance assumption doesn't hold — use Welch's ANOVA instead.

Step 4

Transformation

Why this step — when a group departs from normality, a Box–Cox power transform (y = (xλ−1)⁄λ, or ln(x) at λ = 0) is searched over a grid of λ from −2 to 2, picking whichever value maximizes the transform's profile log-likelihood for this data. If the transformed groups are then consistent with normality, Welch's ANOVA runs on the transformed values — Welch's rather than standard ANOVA, since the transform isn't guaranteed to equalize variances too. If no transform fixes normality, this tool falls back to the fully non-parametric Kruskal–Wallis test instead of trusting a transform that didn't work. Box–Cox needs strictly positive data — if any value is zero or negative, a constant is added to every value first, shown below.

A significant omnibus result here says at least one group differs — it doesn't say which pair. How it's computed — One-way ANOVA partitions total variance into between-group and within-group sums of squares; F = MSbetween⁄MSwithin with df = (k−1, N−k), assuming normal groups with equal variance. Welch's ANOVA (1951) reweights each group by ni⁄si², with an adjusted denominator and a non-integer df₂ — it doesn't assume equal variances, only normality. Kruskal–Wallis ranks all observations across groups and compares mean ranks (H, tie-corrected), needing neither assumption. All p-values use the exact regularized incomplete beta (F-distribution) or incomplete gamma (chi-squared) relations, not approximations. Auto picks standard ANOVA when every group is normal and Levene's test finds equal variances; Welch's ANOVA when every group is normal but variances differ; a Box–Cox transform followed by Welch's ANOVA when a group is non-normal but a transform fixes it; and Kruskal–Wallis when nothing else applies. Eta-squared (η² = SSbetween⁄SStotal) is shown for standard ANOVA and Welch's ANOVA; Kruskal–Wallis instead reports an analogous rank-based epsilon-squared.

How it's computed

Fitting — both models are fit by Newton–Raphson (equivalent to iteratively reweighted least squares) maximizing the exact log-likelihood over all predictors at once — logistic: Σ[yᵢlog(pᵢ)+(1−yᵢ)log(1−pᵢ)] with pᵢ = 1⁄(1+e−ηᵢ); Poisson: Σ[yᵢlog(μᵢ)−μᵢ−log(yᵢ!)] with μᵢ = eηᵢ, where ηᵢ = β₀ + β₁x₁ᵢ + β₂x₂ᵢ + … is the linear predictor. Standard errors come from the observed information matrix (inverse Hessian) at convergence.

How predictor type changes the model — a continuous predictor contributes its raw value as one column of the design matrix, with one coefficient. An ordinal predictor is converted to an equally-spaced numeric score following its category order (typed order, or auto-detected: numeric sort if the categories are already numbers, otherwise the order they first appear) and enters as one column with one coefficient — this assumes the effect of moving up one category is the same size at every step, which is a simplification worth checking against subject-matter knowledge. A nominal predictor with k categories is dummy-coded into k−1 binary columns against a reference category (the first category encountered in the data), so each non-reference level gets its own coefficient, estimated without assuming any order or equal spacing between categories.

Odds ratio / incidence rate ratio / relative risk — for each term, eβ — the multiplicative change in odds (logistic), rate (Poisson), or risk (Poisson for binary outcomes) per one-unit increase (continuous or ordinal) or per category vs. the reference (nominal) — with a 95% CI from eβ ± 1.96·SE(β).

Poisson regression for binary outcomes — logistic regression's odds ratio overstates the relative risk whenever the outcome is common (roughly above 10%), which matters if what you actually want is "how many times more likely," not "how much greater the odds." This option gets around that by fitting the same Poisson log-link model to a 0/1 outcome instead — eβ is then directly the relative risk. Because a 0/1 outcome doesn't really follow a Poisson distribution (its true variance is p(1−p), not equal to its mean), the model's own standard errors would be wrong if used as-is; this tool corrects for that with a robust "sandwich" (Huber–White) variance estimator instead of the model-based one, which is exactly the standard fix used in the epidemiological literature for this technique (sometimes called "modified Poisson regression," Zou 2004). One known quirk: because the Poisson link has no upper bound, the model can imply a fitted probability above 1 for some observations — this is flagged when it happens, and doesn't invalidate the coefficients, but is worth noting when predictors take extreme values.

Likelihood ratio test — 2×(log-likelihood of this model − log-likelihood of an intercept-only model), compared to a chi-squared distribution with degrees of freedom equal to the number of coefficients added (one per continuous/ordinal predictor, k−1 per nominal predictor with k categories). This tests whether the predictors jointly improve on a model with none of them — it's the recommended overall significance test, more reliable than the per-coefficient Wald z-test when effects are large or samples are small.

McFadden's pseudo-R² — 1 − (log-likelihood of this model ⁄ log-likelihood of the intercept-only model). It doesn't mean the same thing as R² in linear regression — values of 0.2–0.4 are often considered a good fit for this measure, not a low one.

Convergence — if Newton–Raphson doesn't settle within 100 iterations, or a coefficient grows extremely large, that usually means perfect or near-perfect separation (the predictors sort the outcome too cleanly for a finite estimate to exist) — the result is flagged rather than reported as if it were a stable estimate.

Overdispersion (count Poisson only) — checked with the Pearson dispersion statistic, Σ(yᵢ−μᵢ)²⁄μᵢ divided by the residual degrees of freedom (n − number of parameters). A value well above 1 means the data are more variable than a Poisson model allows; when that happens, this tool automatically widens all standard errors by √(dispersion) (a quasi-Poisson adjustment) rather than reporting overconfident p-values from the plain Poisson model. Poisson regression for binary outcomes doesn't use this adjustment — the robust standard error handles the (much larger, and different in kind) variance misspecification directly.

Not implemented — interaction terms and negative-binomial regression (a fuller alternative to quasi-Poisson for overdispersion) aren't available in this tool.

A significant intercept (p < 0.10 is the conventional threshold for this test, given its usually low power) suggests funnel-plot asymmetry — from publication bias, but also possibly from genuine differences between small and large studies. How it's computed

Per-study effect — for each 2×2 table (a, b = intervention events/non-events; c, d = control events/non-events; n₁ = a+b, n₂ = c+d): odds ratio OR = ad⁄bc; risk ratio RR = (a⁄n₁)⁄(c⁄n₂); risk difference RD = a⁄n₁ − c⁄n₂. OR and RR are pooled on the log scale, back-transformed for display.

Zero cells — if any of a study's four cells is 0, that study has 0.5 added to all four cells before any calculation involving it (the standard empirical continuity correction) — otherwise its log OR/RR or variance would be undefined. This is applied consistently to that study's contribution to every statistic below, and is flagged in the studies table.

Fixed effect — for OR and RR, the Mantel–Haenszel method (weights bd/n or specific to each measure) is used, with the Robins–Breslow–Greenland (OR) or Greenland–Robins (RR) variance — these remain stable even with sparse data, which is why they're preferred over inverse-variance weighting for fixed-effect OR/RR. Risk difference uses inverse-variance weighting instead (Mantel–Haenszel is not commonly extended to risk difference in the same way).

Random effects — DerSimonian–Laird: between-study variance τ² is estimated from Cochran's Q by method of moments, then each study is re-weighted by 1⁄(vᵢ+τ²) and pooled by inverse variance. This is a closed-form, non-iterative estimator — it doesn't require the CI to be built from a fitted likelihood, unlike REML, which isn't implemented in this tool.

HKSJ adjustment — when enabled, replaces the standard random-effects variance with one based on the residual variation around the pooled estimate, and uses a t-distribution with k−1 df instead of a normal z — this is generally more conservative (wider CIs) and recommended whenever there are few studies, since the plain DerSimonian–Laird CI is known to be too narrow in that situation.

Heterogeneity — Cochran's Q = Σwᵢ(yᵢ−ȳ)² (fixed-effect inverse-variance weights), compared to a chi-squared distribution with k−1 df. I² = max(0, (Q−df)⁄Q) × 100% estimates the proportion of total variation due to real between-study differences rather than chance — conventionally, under 25% is considered low, 25–75% moderate, and over 75% substantial, though these bands are only a rough guide.

Forest plot — each study's square is centered on its effect estimate, sized by its weight in the selected model, with a horizontal line for its 95% CI; the diamond at the bottom shows the pooled estimate, with its width spanning the pooled 95% CI. RR and OR use a log-transformed x-axis so that equal ratios are equal distances apart; RD uses a linear axis.

Funnel plot — plots each study's effect estimate (x-axis) against its standard error (y-axis, inverted so precise studies sit near the top), with pseudo-95% confidence limits (pooled fixed-effect estimate ± 1.96×SE) drawn as a funnel. Asymmetry can indicate publication bias, but can also reflect genuine heterogeneity — it's a prompt to look closer, not a definitive test on its own. Egger's test formalizes this by regressing the standardized effect (effect⁄SE) on precision (1⁄SE) and testing whether the intercept differs from zero.

Not implemented — REML and other iterative random-effects estimators (Paule–Mandel, empirical Bayes), subgroup analysis, meta-regression, and trim-and-fill aren't available in this tool.

How it's computed

Preprocessing — numeric features are z-score standardized (mean 0, SD 1) using training-set statistics only; categorical features are one-hot encoded into one column per category seen in the training data; binary variables (features or the target) are mapped to 0/1. A category seen only at prediction time (playground or batch) that wasn't in the training data is encoded as all-zero — effectively "unseen category" — since the model has no coefficient for it.

Task type — determined automatically from the target's data type: Binary → two-class classification, Categorical → multi-class classification, Numeric → regression. The model list, evaluation metrics, and prediction display all adapt accordingly.

Logistic / softmax regression — a linear model, fit exactly rather than approximately: the two-class case uses the same Newton–Raphson engine as the GLM tab, regression uses closed-form ordinary least squares (no iteration involved), and the more-than-two-class (softmax) case uses gradient ascent with an adaptive, self-correcting step size — a step is only kept if it actually improves the fit, which is checked so training can't silently stop short of converging or drift into a non-converging oscillation the way a fixed learning rate can. Nominal features are dummy-coded against a reference category (k−1 columns, not k), matching the GLM tab's encoding, so the model stays well-posed regardless of how many categories a feature has.

Decision tree — built by recursive binary splitting (CART), choosing at each node the feature and threshold that most reduces Gini impurity (classification) or variance (regression), down to the chosen max depth.

Random forest — an ensemble of trees, each grown on a bootstrap resample of the training rows; each split is also restricted to a random subset of the features (√p for classification, p/3 for regression, following the standard Breiman recipe) so the trees decorrelate from one another rather than all leaning on the same dominant predictor. Predictions are averaged (regression) or majority-voted with class probabilities from the vote fractions (classification). This generally trades a little training time for a more stable, less overfit result than a single tree.

k-Nearest Neighbors — predicts a new point from the k closest training rows by Euclidean distance (after standardization) — majority class fraction for classification, mean value for regression. No explicit "training" step beyond storing the data.

Neural network — a multilayer perceptron built and trained with TensorFlow.js (loaded from a CDN only when you train one), with your chosen hidden-layer sizes and activation function, Adam optimization at your chosen learning rate, and a sigmoid, softmax, or linear output layer depending on the task. The live loss curve is training loss on a further split of the training data (not the held-out test set), so the test-set evaluation below stays honest.

Evaluation — all metrics are computed on the held-out test set only, never on data the model trained on. Precision, recall, and F1 are macro-averaged across classes for multi-class problems. The ROC curve and AUC are shown only for two-class problems.

Not implemented — support vector machines, cross-validation / hyperparameter search, feature importance, stratified splitting, and REML-style iterative estimators aren't available in this tool.

How it's computed

Algorithm — k-means clustering: starting from k initial centroids chosen by the k-means++ scheme (spread out rather than picked purely at random, which reliably gives a better starting point), each row is repeatedly assigned to its nearest centroid (Euclidean distance, on standardized/encoded features) and each centroid recomputed as the mean of its assigned rows, until assignments stop changing. To avoid a poor result from an unlucky starting point, this runs 10 times from different random starts and keeps the run with the lowest within-cluster sum of squares (inertia) — validated by confirming this substantially reduces the worst-case outcome compared to a single run on deliberately awkward (uneven, overlapping) synthetic data.

Suggested number of groups — k-means is run for every k from 2 up to min(10, n−1), and each is scored with the average silhouette coefficient — for every row, how much closer it is to its own group than to the next-nearest one, averaged across all rows and ranging from −1 (likely misclassified) to +1 (clearly the right group). The k with the highest average silhouette is suggested, but you can override it with the slider — there's no single "correct" number of groups in unsupervised learning, only a statistical suggestion.

Preprocessing — the same as the supervised module: numeric features are z-score standardized, categorical features are one-hot encoded, both using statistics from the uploaded dataset. A category seen only in the playground or a batch file that wasn't in the original data is encoded as all-zero.

Group profile — the mean of each feature within each group, on its original scale (un-standardized) — a quick way to see what distinguishes one group from another.

Assigning new data — a new row (from the playground or a batch file) is assigned to whichever centroid it's closest to, using the same standardization learned from the original data. There's no "confidence" in the way a classifier has one — the relative distances to each centroid are shown instead, as a sense of how clear-cut the assignment is.

Limitations — k-means assumes groups are roughly round and similarly sized in the standardized feature space, and can be misled by features that aren't actually meaningful for grouping — the choice of which features to include matters as much as the algorithm itself. There's no ground truth to check a clustering against, unlike the supervised module's held-out test set: these groups describe structure in the data, not a validated prediction.
